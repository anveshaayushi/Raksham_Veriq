# Q&A sheet: likely judge questions per rubric row, with direct answers ("we don't know" where true)

| Rubric row | Likely question | Direct answer |
|---|---|---|
| Working prototype | Can I try my own chat? | Yes, paste it now; the answer is computed live. Chats without timestamps are refused (we say why). |
| Spot-check accuracy | How accurate is it on data it never saw? | Chats: 96.2% on our held-out synthetic test when first run blind (100% after a fix made with those failures in view, so not blind). Blind AI-generated and teammate sets: see RESULTS.md (not run if empty). Voice: AUC 0.77 on ASVspoof LA eval, close to its training data. |
| Spot-check accuracy | What are your false positives? | 0/178 genuine payees accused on the synthetic test; 0/42 same-firm names called a discrepancy in our name-pair set (3/42 before the 25 Oct fixes); on the AI blind chat set 7/40 genuine chats accused before fixes, 1/40 after (C-43); voice flags ~16% of genuine clips (ASVspoof eval). |
| Spot-check accuracy | Name a failure. | A spaced-out UPI ID is not found (live journey J2); our synthetic TTS demo clip is not flagged; "BLUE RIVER" vs "BlueRiver" is called a discrepancy. |
| Own engineering | What did you write vs download? | ENGINEERING_WALKTHROUGH.md: parser, extractor, matcher, rules, registry, reports, app, evaluation are ours; AASIST, OpenCV, Streamlit, ffmpeg are not. We trained heads on AASIST embeddings, not AASIST itself. Claude (Anthropic) wrote code under our direction. |
| Alert and response | What does the user do after the alert? | Do not pay, check the payee name in their own bank app, ask a person to review, download a report pack and file it themselves (1930 / cybercrime.gov.in). VERIQ itself blocks and files nothing. |
| Alert and response | Are safeguards running or described? | Running and tested: no chat or audio left on disk after a full check (test), offline mode with outgoing connections blocked (test), delete-my-data (test), human review with audit trail (test). |
| Delivery vs plan | What did you cut? | Speech-to-text (paste text instead), team's own voice recordings, OCR. PLAN_VS_DELIVERED.md lists each with the reason. |
| Problem and user | Who is the user? | Meera, a first-time investor pulled into a WhatsApp "advisory" group (SEBI's 21 May 2025 warning describes this pattern). Loss figures are sourced in PROBLEM_USER.md; how many could be saved: we don't know. |
| Deployability | Who runs it and what does it cost? | A bank fraud desk or cyber cell (reviewer desk) or a citizen web app; open source, CPU only; cost estimates with assumptions in DEPLOYABILITY.md; a pilot needs consented data, DPDP review, reviewers, HTTPS. No partnership claimed. |
| Communication | Are your numbers real? | Every number in RESULTS.md has its command, date and data; synthetic sets say "generated by us". |
| Live journey | Can the jury change the scenario? | Yes: edit any line in the scenario player, change the payee or the bank-app name, add a voice note, replay. |
| Adversarial | How would you beat it? | Mule account in the firm's exact name; pressure without keywords; spaced-out UPI IDs; payment links outside the chat; unseen voice engines. EVASION_LAB.md says what we would change. It can be fooled; it is built not to falsely reassure. |
| Responsible AI | What happens to a genuine user flagged by mistake? | Scenario D: the alert says why; one click asks for review; a reviewer overturns with a reason; time shown; audit trail without raw identifiers. Human checking time: we don't know yet (not measured with real reviewers). |
| Responsible AI | Do you store my data? | No raw chat or audio is kept; the registry stores keyed hashes only (pseudonymisation, not anonymity). |
| Any | What don't you know? | Accuracy on real victims' chats; voice on Hindi and real WhatsApp notes; reviewer time per case; how users react to "Inconclusive". |
