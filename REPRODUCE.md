# REPRODUCE: from a clean machine to every reported number

Organisers' rules covered: (1) generation code for our synthetic data is submitted, (2) the test workflow is part of
the submission, (3) reproducibility instructions come with the results, (4) test completeness is measured.

**Plain words.** One command rebuilds our synthetic test data, runs every test, measures how much of the code the tests
exercise, re-runs the benchmarks and compares each number with the one we committed. If anything differs, it says so
and exits with an error. Nothing uses the internet except the first `pip install`.

## 1. Quick start

Windows 11 (PowerShell, from the `veriq` folder):

```powershell
winget install Gyan.FFmpeg                      # once; then open a NEW terminal
powershell -ExecutionPolicy Bypass -File reproduce.ps1
```

Linux / macOS:

```bash
sudo apt install ffmpeg        # or: brew install ffmpeg
python3 -m venv .venv && . .venv/bin/activate
python -m pip install -r requirements-dev.txt
make reproduce                 # same as: python scripts/reproduce.py
```

Expected end of the output: a table of checks and **ALL CHECKS PASSED**. The full table is written to
`results/REPRODUCE_REPORT.md`. `make reproduce-full` (or `reproduce.ps1 -Mutation`) adds the mutation check.

`make reproduce` regenerates the four chat/campaign files and requires them to be **byte-identical** to the committed
ones (checked on Linux; the generators write `\n` line endings so Windows gives the same bytes).

**The circularity limit (read this before quoting the chat numbers).** The chat benchmark was generated by the same team
that wrote the rules. It checks that the code does what we designed on many varied chats (formats, decoys, three
changing payees, gateways, Hinglish), but it cannot show how well our design matches real scams: a scam written in a
way we did not imagine is, by construction, not in it. That is why Q2 adds a public text dataset and a blind set
written by teammates who have not read the rules. Treat 96.2% (first blind run; 100% after a fix made with the failures in view) as "the code matches its specification on synthetic
chats", not as real-world accuracy.

**Voice set rebuild.** The committed voice set was built on the Linux sandbox before a Q1 fix that sorts the FSDD file
list. A rebuild today picks other recordings of the same six speakers, so expect the voice numbers within about
±0.02 (AUC) to ±0.05 (rates), not identical. To check the exact committed clips, compare against
`bench/voice/voiceset_manifest.csv` (file, label, speaker or voice, split, SHA-256). The 52 MB set itself can be shared
as a release file on request.

## 5. Rebuilding the voice result from scratch (about 30 min on a laptop CPU)

```bash
python -m pip install -r requirements-voice.txt kokoro-onnx
git clone https://github.com/clovaai/aasist external/aasist
git clone https://github.com/Jakobovski/free-spoken-digit-dataset external/fsdd
# kokoro-v1.0.onnx and voices-v1.0.bin: download from the kokoro-onnx model-files release; check the SHA-256 above
python -m bench.voice.make_set --fsdd external/fsdd/recordings --kokoro kokoro-v1.0.onnx --voices voices-v1.0.bin --out voiceset
python scripts/reproduce.py --voice-data voiceset --aasist external/aasist
```

PowerShell: `certutil -hashfile kokoro-v1.0.onnx SHA256` prints the checksum to compare.
