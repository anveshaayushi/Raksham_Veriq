# Chat-side benchmark (synthetic) · FINALE, 24 Oct 2026

**What it measures:** VERIQ's chat side end to end (parse → extract payees → user's typed payee name → rules) on
synthetic WhatsApp-style chats with known answers. **Not** the voice detector (Claude B), and **not** real-world accuracy.

**Method**
- `python -m bench.generate` writes two splits with different phrasings, firm names, mule names and decoys
  (e-mails, phone numbers, order numbers, URLs): `dev` (120 chats) and `test` (300 chats, seed 20261024).
- `dev` was used to find and fix bugs. `test` was run **once**, after the fix, and not tuned on afterwards.
- Ground truth is set by the generator (what it put in), not by running VERIQ.
- Expected answers follow the deck's rules: unrelated business name → NAME_DISCREPANCY; personal-looking name,
  payment gateway, or no name check → INCONCLUSIVE; matching name → NO_MAJOR_ISSUE (with "This is not a guarantee.").

**Results** (`python -m bench.run test`, 24 Oct 2026, file `bench/results_test.json`)

| Measure | Result |
|---|---|
| Payee extraction (UPI IDs + account numbers) | precision 1.00, recall 1.00 (399 / 399, 0 false pickups) |
| Decision per payee matches the expected answer | **96.2%** (384 / 399) |
| False alarms: genuine payees given an accusing answer | **0 / 178** |
| Scam payees given "No major issue" | **0 / 221** |
| Time per chat (rules only, laptop CPU) | median 0.37 ms, max 1.0 ms |

**Failure case (named):** 15 / 399. Every one is the shown name "KRISHNA DAIRY FARM". "Krishna" is a common given
name, so the matcher called it personal-looking and answered INCONCLUSIVE instead of NAME_DISCREPANCY. This is the
safe direction (no false accusation, still "don't pay yet"), but it is a miss. Fixing it would need a new, unseen test
set to measure honestly.

**History (dev split):** first run 79.0% (34 misses: shop names such as "BALAJI GARMENTS" were treated as personal
names); fixed by calling a name personal only if it contains a common Indian given name or surname; dev then 100%.
Dev numbers are not reported as results because dev was used for fixing.

**Limits:** synthetic, English, generated by the same team that wrote the rules; it shows the pipeline is consistent
and robust to formatting and decoys. It says nothing about how often real victims' apps show which names.

**Run 2 (24 Oct, after the look-alike and cue changes, which were made for the red-team brief, not from test
failures):** identical numbers: 399/399, 96.2%, 0/178 false alarms, 0/221 scams cleared, same 15 misses.

**Red-team set:** `python -m bench.adversarial` (look-alike names, genuine variants, obfuscated cues, QR payees,
short audio + pressure, benign sentences). Results and known gaps are in RESULTS.md ("Red-team log").
